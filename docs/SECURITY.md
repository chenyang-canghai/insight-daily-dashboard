# 安全与隐私

## 数据边界

- GitHub 仓库：只保存公开日报、来源登记和构建产物输入。
- IndexedDB：保存收藏、备注、答题记录、错题和用户设置；默认不上传。
- GitHub Secrets：当前生产来源不需要 Secret；未来用户自有密钥只供 Actions 后端任务使用，不得以 `NEXT_PUBLIC_` 前缀暴露。

## 控制措施

- 外部 URL 只接受 `http:`/`https:`；优先 HTTPS，个别政府旧 RSS 仅作元数据入口且不绕过其访问控制。渲染外链时使用 `rel="noopener noreferrer"`。
- Markdown 默认按纯文本或受控组件渲染；不使用未经清洗的 `dangerouslySetInnerHTML`。
- LLM 只接收已采集证据，输出经 Pydantic 验证并最多修复两次；失败内容不发布。
- 日报检查未来时间、空字段、重复事件、禁用投资措辞、来源存在性和疑似密钥。
- Actions 使用最小权限、并发锁、超时、固定主要 Action 版本，日志不回显 Secrets。
- 导入收藏 JSON 时校验版本、大小和字段；清空数据必须二次确认。
- Service Worker 只缓存同源公开页面、公开日报和静态资源，不缓存外部来源页面、用户收藏或任何凭据；新闻与最新日报采用网络优先策略。
- 当前 PWA 不申请通知、定位、相机或通讯录权限。

## 威胁模型

主要威胁包括恶意网页提示词注入、上游数据污染、依赖投毒、付费内容误转载、API Key 泄露、旧行情误标、XSS 和导入文件资源耗尽。每个数据项保留来源 ID、生成时间、内容哈希与验证错误，发布器采用失败关闭策略。

## 事件处理

发现密钥泄露时先撤销密钥，再删除公开历史并轮换相关凭据；仅从 Git 历史删除字符串不能使已泄露密钥恢复安全。发现数据错误时保留更正记录，更新清单和内容哈希，不静默覆盖事实历史。
