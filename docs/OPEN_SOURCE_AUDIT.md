## 逐项审计

### 1. RKiding/Awesome-finance-skills

- **核验结果**：根目录 `LICENSE` 为 Apache License 2.0。仓库包含 `alphaear-news`、`alphaear-stock`、`alphaear-sentiment`、`alphaear-signal-tracker`、`alphaear-logic-visualizer`、`alphaear-reporter`、`alphaear-search`。
- **有价值的思想**：多来源新闻聚合；行情与基本面工具分层；信号使用“增强/减弱/证伪/不变”状态；把影响链可视化；报告采用计划、撰写、编辑、图表的分阶段流程。
- **是否复用文件**：否。本项目独立实现数据契约、适配器、影响链组件和报告流程。
- **未直接采用的理由**：其新闻源包含社交热榜和预测市场，不满足本项目“重大事实优先原始来源、原则上双源核验”的默认标准；股票技能同时面向 A/H/美股，范围大于本项目；部分功能依赖 agent 框架、SQLite 或模型预测，增加静态站点复杂度。
- **版权风险**：聚合结果仍受原始新闻站点条款约束；不得把抓取成功等同于可转载。只保存链接、必要元数据和原创摘要。
- **安全风险**：外部网页内容可能含提示词注入、恶意 HTML、跟踪参数或不可信重定向；第三方模型输出不可直接发布。
- **采用结论**：仅采用“来源分级、适配器、证伪状态、影响链、编辑复核”这些抽象思想。

### 2. ZhuLinsen/daily_stock_analysis

- **核验结果**：根目录 `LICENSE` 为 MIT（Copyright 2026 ZhuLinsen）。仓库包含市场服务、报告 Schema、仪表盘组件、测试、`SKILL.md` 和 `.github/workflows/00-daily-analysis.yml`。
- **有价值的思想**：统一数据源与降级；交易日保护；市场复盘与报告归档；Actions 的并发控制、超时、手动输入与失败诊断；前端区分加载、空数据、过期和错误状态。
- **是否复用文件**：否。MIT 允许复用，但当前需求更轻量，直接搬用会引入多市场、通知、机器人、服务端 API 等无关复杂度。
- **版权风险**：行情和资讯由下游数据提供方产生，MIT 只覆盖代码，不自动授予数据再分发权。
- **安全风险**：工作流涉及大量 Secrets、多通知渠道和外部数据服务；照搬会扩大密钥泄露与供应链攻击面。其 `force_run` 思路也不能用于把非交易日旧行情伪装为当日数据。
- **采用结论**：独立实现小型 `MarketProvider` 接口、显式冲突记录、交易日二次校验、报告归档和幂等工作流。

### 3. akfamily/akshare

- **核验结果**：根目录 `LICENSE` 为 MIT（Copyright 2019-2026 Albert King）。
- **使用方式**：在 `market` 可选依赖组中使用，不进入浏览器包；由 Python 数据生成层调用。
- **复用内容**：仅调用公开 Python API，不复制仓库源码。
- **数据与版权风险**：AKShare 的 MIT 许可证覆盖软件，不代表东方财富、交易所等上游数据可无限制再分发。日报只保存研究所需字段、来源、时间、单位与质量状态，不批量镜像原始数据库。
- **稳定性风险**：免费数据接口可能改版、限流或暂时不可用，必须设置超时、重试、缓存、备用源和“数据不足”状态，禁止静默伪造。
- **采用结论**：采用为可选首选源；无网络或接口失败时退回 demo/最近有效交易日并显式标注。

### 4. hsliuping/TradingAgents-CN

- **核验结果**：当前仓库为混合许可证。`tradingagents/`、`cli/`、`scripts/`、`docs/`、`examples/`、`web/` 等按其说明使用 Apache-2.0；`app/` 与 `frontend/` 使用专有许可证，禁止未授权再分发、修改和商业使用。
- **是否直接依赖**：否。
- **可参考思想**：把市场、新闻、基本面、估值、风险和最终结论分开；保留多种情景、未知信息和证伪条件。
- **明确排除**：不读取或复制 `app/`、`frontend/` 的实现与界面；不引入 MongoDB、Redis、多服务编排或自动交易；不复制示例研究结论。
- **安全风险**：多智能体会增加外部工具调用、提示词注入、事实漂移、成本失控与不可追溯风险。
- **采用结论**：仅在本项目原创 Schema 中体现“证据—分析—风险—情景—证伪”的报告顺序。

### 5. xianhua1/Huahuagongkao

- **核验结果**：GitHub API 未识别到根仓库许可证，根目录也无统一 `LICENSE`。子目录中的若依许可证不能推定覆盖作者新增的题库、截图、文案和业务代码。
- **是否直接依赖**：否。
- **可参考思想**：每日一练、答题计时、答案折叠、错题本、间隔复习、学习统计、申论材料与评分点。
- **明确排除**：不复制约 1.9 万道行测题、申论题库、SQL 数据、截图、教程、范文、模板、题目图片、代码或产品文案。
- **版权风险**：真题、解析、培训材料与汇编数据库可能分别受著作权、数据库权益或站点条款影响；“网上可见”不等于可再分发。
- **安全风险**：README 示例包含默认数据库口令；本项目不沿用。AI 评分输入可能含个人学习内容，第一版只保存在 IndexedDB。
- **采用结论**：只参考通用交互模式；demo 题全部由本项目原创并标记 `source_type: original_demo`。

## 本项目的复用清单

### 直接依赖

- `akshare`：仅 Python 可选依赖，遵守 MIT 许可证并保留依赖声明。
- 其余运行依赖分别以各自包管理器锁文件和许可证清单为准。

### 只参考、不复制

- 多来源数据适配器与降级。
- 新闻事件去重、影响链与证伪状态。
- 金融报告的证据、情景、风险和未知信息分层。
- 每日一练、错题本、间隔复习和学习统计的通用产品模式。

### 永不纳入仓库

- 付费新闻全文、登录后内容、商业题库与来源不明真题。
- 第三方截图、品牌素材、未授权图片和大段原文。
- 任何真实 API Key、Cookie、账号、券商凭据或个人答题记录。
- TradingAgents-CN 的 `app/`、`frontend/` 专有代码。

## 上线前复核

1. 通过 lockfile 固定依赖，并在 CI 中执行依赖审计与密钥扫描。
2. 每次升级 AKShare 前运行适配器契约测试。
3. 新增数据源时同时记录使用条款、抓取频率、允许保存的字段和退出机制。
4. 若未来想复用第三方文件，必须重新核验该文件所在提交的许可证并保留版权与 NOTICE；当前版本没有复制任何受审计仓库文件。
